主要流程逐步說明

  1. ①LicenseGate 把序號透過 preload 白名單的 api:license:verify 送到主程序（空白或非字串直接擋下）。
  2. ②license.service 把「序號 + 機碼 + 本機綁定紀錄 + 版本」POST 到授權伺服器（Lambda Function URL），15 秒逾時。客戶端不再持有任何 Whop Key。
  3. ③Lambda 從 SSM 讀出 Whop Key（暫存在記憶體），向 Whop 查詢序號、比對機碼；首次啟用時合併 metadata 後寫回綁定。只回傳結果代碼，不回傳 Whop 原始資料。
  4. ④授權通過後，前端呼叫 api:license:activate，主程序開始啟動 Bot。
  5. ⑤從 SQLite 讀出 Bitfinex API Key 密文，交給 safeStorage 解密；解密失敗回傳 null，直接中止，不啟動子程序。
  6. ⑥fork('bot-runner.js')，金鑰只放在子程序的環境變數；子程序異常結束時 3 秒後自動重啟。
  7. ⑦啟動檢查：校時（timeapi.io，失敗改用 Bitfinex Date 標頭）、API Key 權限檢查（有提幣／交易權限就退出），然後建立 WebSocket。
  8. ⑧Bitfinex WS 推送 funding 錢包變動，可用餘額超過門檻就觸發。
  9. ⑨防抖 3 秒後執行 executeStrategy（4 分鐘逾時保護）。
  10. ⑩定價：短天期 VWAP、EMA 動態基準、多模型取最強底價、波動率加成，再用 calculatePeriod 選天期。
  11. ⑪掛撤單：資金 ≥ 1000 用階梯、否則二分法；舊單依時間門檻、利用率、絕對底線、賤賣防護決定是否撤回。
  12. ⑫bfx.service 簽章送出 REST 請求，每筆間隔 0.2 秒避免被拒。
  13. ⑬用 Bitfinex 回傳的真實 Offer ID 寫入 offers；解析失敗就拒寫。
  14. ⑭sync／stats 同步帳本與利息、寫資產快照與 credit 生命週期。
  15. ⑮子程序用 stdout／stderr 送日誌、用 process.send 送 system-alert。
  16. ⑯main.js 遮罩敏感字串（sanitizeLog）後寫 logs，並暫存系統警告。
  17. ⑰server.js 的 IPC handler 依前端請求查詢 SQLite。
  18. ⑱透過 webContents.send 推送 bot-log、bot-status-update、system-alert 到畫面。

容易搞混的選擇

容易混淆差別本專案的選擇
主程序 vs 子程序主程序管視窗與 IPC；子程序跑策略fork 隔離：策略當掉不拖垮畫面，金鑰只存在子程序環境變數
客戶端 vs 伺服器端驗證Key 放安裝檔裡 vs 只放雲端v4.2.0 起改由 Lambda 驗證；客戶端只送序號與機碼，安裝檔解開也拿不到 Whop Key
DENIED vs 503序號確定不行 vs 暫時查不到只有 DENIED 才清快取擋人；503（Whop 掛掉、逾時、我方 Key 失效）一律走 24 小時離線快取
本機打包 vs CI 打包你的電腦 vs GitHub Actions本機輸出到專案外（避免 VS Code 鎖 app.asar）、不發佈；推 v* tag 才由 CI 打包三平台並更新 versions.json
WebSocket vs RESTWS 是交易所主動推送；REST 是我方主動詢問WS 負責「何時觸發」，REST 負責下單與查詢；Watchdog 每 5 分鐘全同步補漏
null vs 0／[]查詢失敗 vs 真的沒有失敗一律回 null，呼叫端跳過本輪；改合約要搜遍所有呼叫端
offers vs credits掛單中（還沒人借）vs 已借出Bitfinex 網頁「掛單」看 offers；借出統計看 credits
二分法 vs 階梯拆兩筆 vs 依序拉高利率分多筆資金 ≥ 1000 才用階梯，否則二分法
invoke vs on畫面主動查詢 vs 主程序主動推送兩者都要列在 preload 白名單，否則前端呼叫不到
stdout vs stderrconsole.log vs console.warn/errorstderr 只進終端機頁籤與 DB，不印到 PowerShell
start:win vs dev載入 client/dist vs Vite 即時編譯改前端後要先 npm run build，否則看到舊版
PM2 vs 自管 fork外部行程管理器 vs Electron 自己管早期用 PM2，現在由 main.js 自管並內建崩潰重啟；註解、bfx-bot-usdt 等名稱與 asarUnpack 的 @pm2 是遺留

每一區的重點

Renderer（React）只碰白名單

React + Vite + Tailwind，i18n 中英文、深淺色。不能直接用 Node，所有資料都靠 window.electron.invoke／on。授權未通過時只渲染 LicenseGate。

preload.js安全邊界

contextIsolation: true、nodeIntegration: false，只用 contextBridge 暴露白名單內的通道。

const allowed = ['api:stats', 'api:system:alerts', /* … */];
invoke: (ch, ...a) => allowed.includes(ch)
  ? ipcRenderer.invoke(ch, ...a) : Promise.reject()

Main 主程序生命週期・IPC

單例鎖、系統列、防休眠、開機自啟、關閉前安全收尾；IPC 參數驗證（symbol 白名單、api:open-external 協定檢查、api:vwap 白名單）。

const key = decryptForBot(keys.apiKey);
if (key === null) return; // 解密失敗不 fork
fork('bot-runner.js', [], { env: { SECURE_API_KEY: key } });

Bot 子程序策略核心

單一子程序同時服務 fUSD／fUST／fBTC，每個幣種的停止狀態分開記錄（userStoppedMap）。策略逾時 4 分鐘、同步 3 分鐘、WS 重連 15 秒。

// bfx.service：500/429 觸發熔斷 30 秒，回傳 null
if (credits === null) {
  console.warn('API error, skipping this snapshot');
  return null;   // 保留上一筆正常資料
}

SQLite7 張表

configs（設定、密文金鑰、EMA）、offers、credit_lifecycle、stats、ledgers、logs、eula_agreements。每 12 小時自動清理過期資料。*.db 絕不進版控。

雲端服務

Bitfinex（REST 下單、WS 推送；nonce 以時間戳遞增，時鐘倒退或兩支程式共用一把 Key 會出現 nonce: small）、Whop（會員資料，只由 Lambda 存取）、License Lambda（授權驗證，us-east-1）、Telegram（推播）、GitHub versions.json（更新檢查）。

安全性總表

  • Whop API Key 只存在 AWS SSM（SecureString），Lambda 的 IAM 角色只能讀這一個參數；安裝檔、.env、GitHub Secret 都已移除
  • 打包前掃描所有會被打包的檔案，發現 apik_ 就中止；runtime-config.json、.env.* 一律排除
  • Bitfinex API Key 用 OS 金鑰庫（safeStorage）加密存放，只在子程序解密使用；啟動時拒絕有提幣／交易權限的 Key
  • 日誌輸出前遮罩金鑰；Lambda 日誌只記結果代碼，不記序號與機碼
  • Lambda 擋掉非 POST、超過 2KB、格式不合法的請求，序號含 ../ 不會送到 Whop
  • 換 Whop Key 不用重新部署：Lambda 收到 401/403 會自動重讀 SSM
